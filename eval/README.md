# 공고 추출 정확도 측정

> **추가 측정(holdout):** 개발 중 한 번도 보지 않은 새 공고는 `eval/holdout/`(postings, answers.csv)에 따로 두고 `python eval/run_eval.py --set holdout`으로 채점합니다. 기존 20건과 섞지 않습니다.
>
> **최종 측정 세트 (11/20 확정):** `answers_real.csv` + `postings/` 20건. 잡알리오 공공기관 실제 공고에 대해 AI 초안 정답을 신민혁(TI 7건)·신나영(MH·NY 14건)이 원문과 대조해 검수했고, 2024년 공고(mh07)는 제외했습니다. 정답은 공고 본문(.txt)에 적힌 내용만 인정합니다(첨부 공고문 내용 제외). 시연용 합성 공고 정답은 `sample_answers.csv`로 옮겨 측정에서 뺐습니다.

AI가 실제 채용공고에서 **마감일**과 **시험·어학 요건**을 맞게 뽑는지 사람이 만든 정답과 비교해 채점합니다.
결과(예: "마감일 19/21 정확")는 소개서와 발표에 근거로 씁니다.

## 일정

| 언제 | 할 일 | 누가 |
|---|---|---|
| 11/20(금) 21:00까지 | 공고 모으고 정답 작성 → GitHub에 올리기 | 신나영 |
| 11/21(토) 오전 | 1차 측정, 틀린 항목 분석 | 이신혁 |
| 11/21(토) 중 | AI 규칙 수정 후 2차 측정 | 이신혁 |
| 11/22(일) | 결과를 소개서·발표 자료에 반영 | 전체 |

정답이 틀리면 점수도 틀리게 나오므로, 1차 측정 뒤 "정답표 확인 요청"이 오면 해당 공고를 다시 봐 주세요.

## 범위

- **15건 이상** (목표 20건). 시간이 부족하면 15건을 먼저 올리고 나머지는 이어서 올려도 됩니다
- **IT·데이터 직무** 공고 위주 (신입·인턴 우선)
- **시험·어학 요건이 있는 공고를 절반 이상** (토익, 정보처리기사, SQLD, ADsP)
- **마감일이 없는 공고**(상시 채용, 채용 시 마감)도 1~2건 포함
- **본문을 글자로 복사할 수 있는 공고만** 사용. 공고 전체가 이미지인 경우는 건너뛰고, 몇 건이었는지 Notion 진행 공유 게시판에 적어 주세요. 서비스의 한계로 소개서에 씁니다.
- 출처는 사람인·잡코리아·원티드·기업 채용 페이지 어디든 가능

## 하는 법

### 1. 공고 본문 저장
- 공고 본문 전체를 복사해 메모장에 붙여 넣고 **UTF-8**로 저장합니다.
- 담당자 이름·전화번호·이메일 같은 **개인정보는 지웁니다.** 회사명은 그대로 둡니다.
- 파일 이름은 `ny01.txt`, `ny02.txt` … 순서대로 붙입니다.

### 2. 정답 작성
`answers_ny.csv`에 공고마다 한 줄씩 씁니다.

엑셀로 열어도 되고, GitHub 웹에서 ✏️로 바로 고쳐도 됩니다. 첫 줄(칸 이름)은 지우지 않습니다.

| 칸 | 쓰는 법 | 예 |
|---|---|---|
| file | 공고 파일 이름 | ny01.txt |
| deadline | 지원 마감 | 2026-12-01 23:59 |
| exams_required | 필수 시험·어학 요건 | toeic>=700 |
| exams_preferred | 우대 시험·어학 요건 | info_engineer;sqld |
| count_required | (비워도 됨) 필수 요건 전체 개수 | |
| count_preferred | (비워도 됨) 우대 요건 전체 개수 | |

예시 한 줄:
```
ny01.txt,2026-12-01 23:59,toeic>=700,info_engineer;sqld,,
```

### 3. 올리기
https://github.com/lsh99520/JobParser/tree/main/eval 에서
- `postings` 폴더로 들어가 **Add file** → **Upload files**로 공고 파일 업로드
- `answers_ny.csv`를 열고 ✏️로 정답 붙여 넣기 → **Commit changes**

올리면 Notion 진행 공유 게시판에 자동으로 기록됩니다.

## 정답 작성 규칙

### 시험 코드
목록에 있는 시험만 씁니다. 목록에 없는 시험(컴활, OPIc, 토익스피킹, 산업기사 등)은 적지 않습니다.

| 코드 | 시험 |
|---|---|
| `toeic` | TOEIC |
| `info_engineer` | 정보처리기사 |
| `sqld` | SQLD |
| `adsp` | ADsP |

여러 개는 `;`로 구분하고, 해당하는 게 없으면 칸을 비웁니다.

### 필수와 우대 구분
- "지원자격", "자격요건", "필수"에 있으면 **필수**
- "우대사항", "우대", "가점"에 있으면 **우대**
- 어느 쪽인지 분명하지 않으면 **우대**

### 자주 헷갈리는 경우
| 공고 문구 | 정답 |
|---|---|
| 토익 700점 이상 | `toeic>=700` |
| 공인 어학성적 보유 (점수 없음) | 적지 않음 (토익을 특정하지 않음) |
| 토익 700 이상 또는 이에 준하는 어학 성적 | `toeic>=700` |
| 토익 점수 제출 (점수 기준 없음) | `toeic` |
| 정보처리기사 또는 SQLD 보유자 | `info_engineer;sqld` |
| 정보처리산업기사 | 적지 않음 (정보처리기사와 다른 자격) |
| 데이터 관련 자격증 우대 (이름 없음) | 적지 않음 |
| 정보기술분야 기사 이상, SW 기술자의 '기사 자격' (이름 없이 정보처리기사가 속하는 분야) | `info_engineer?` (허용: 뽑아도 안 뽑아도 맞음) |

### 마감일
| 공고 문구 | 정답 |
|---|---|
| 2026.12.01(화) 23:59 | `2026-12-01 23:59` |
| ~12/1(화) 18시 | `2026-12-01 18:00` |
| ~12월 1일까지 (시각 없음) | `2026-12-01` |
| 상시 채용, 채용 시 마감 | `없음` |

연도가 안 적혀 있으면 실제 마감 연도를 씁니다.

## 실행 (이신혁, API 키가 있는 PC)
```
python eval/run_eval.py
```
- `answers.csv`와 `answers_*.csv`를 모두 읽어 채점합니다. 공고 파일이 없는 줄은 건너뜁니다.
- 결과: `eval/report.md`(요약과 틀린 항목), `eval/results.csv`(공고별 상세)
- 정답표만 고쳤다면 `python eval/run_eval.py --cached`로 API 호출 없이 다시 채점
